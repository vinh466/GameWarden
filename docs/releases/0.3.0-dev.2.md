# GameWarden 0.3.0-dev.2

## Data impact

- **From `v0.3.0-dev.1` or `v0.2.0-rc.20`:** update only. The database schema is the same.
- **From `v0.2.0-rc.19` or older:** back up before updating. The observability migration landed in
  `v0.2.0-rc.20`, so the first start after the update may change the database.

Back up the usual folders before updating from an older build:

```text
C:\GameWarden\instances\<id>\data        worlds and saves
C:\GameWarden\db\gamewarden.db           servers, settings, Owner account
C:\GameWarden\instances\<id>\mods        if mods or configs changed
```

## What changed

- No runtime code change from `v0.3.0-dev.1`. This is a re-cut of the observability build on the
  forward-only development line after reviewing [ADR-0027](../../decisions/0027-development-releases-move-forward.md).
- The release flow now runs the same CI gate as `main`, requires the tag to be on `main`, and publishes
  `docs/releases/<version>.md` as the release body the panel shows before an update.
- Includes the system log and Discord notification work from `v0.2.0-rc.20`.

## What to test on the VM

- [ ] `gamewarden update --check` says the running version is current after the update; `--prerelease` is
  no longer a command because every development build is a pre-release.
- [ ] Open **System → Version & updates**: newest version, checked time, release notes and last result.
- [ ] Open **System → Logs**: filter by server/job/level/text; open a row for the exception/data drawer.
- [ ] Create an Agent token with `agent.logs.read`, enable diagnostics, and call
  `/api/v1/agent/logs?source=system&level=warn,error&limit=50` (403 while diagnostics is off).
- [ ] Add a Discord destination, save a webhook, test it, then trigger a failed job or a crash.
- [ ] Check the delivery log: `sent`/`failed`, attempts and retry; the webhook URL is never shown again.
- [ ] Confirm no webhook URL or password appears in the panel, `notifications.json`, the database or
  `logs/core-*.log`.
- [ ] Update from the panel: the release notes and backup warning appear before the confirmation; games
  keep running while Core restarts.

## After updating

- [ ] Server list still shows the instances and they start.
- [ ] Worlds and mod sets are the expected ones.
- [ ] If you came from `v0.2.0-rc.19` or older, confirm the database and instance settings survived.
