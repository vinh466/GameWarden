# GameWarden 0.3.0-dev.5

## Data impact

- **From `v0.3.0-dev.4` or newer:** update only. No database change.
- **From `v0.3.0-dev.3` or older:** update only; the `notification_status` table from dev.4 is added on first start.
- **From `v0.2.0-rc.19` or older:** back up before updating. The observability migration landed in `v0.2.0-rc.20`.

## What changed

- **System → Notifications** now has a help drawer for every non-obvious option: destination id/name,
  webhook, mode, language, minimum severity, topics, servers, mention role, panel URL, interval/window,
  enabled, Test and the delivery log.
- Dropdown options show a short description under the label for mode, language, minimum severity, topics
  and servers, so the choice is understandable without opening the drawer.
- The topic catalog in the Topics dropdown shows its category and default severity.
- The mock panel now exposes all three modes and the current development version.
- No backend or database change.

## What to test on the VM

- [ ] Open **System → Notifications → Add destination**.
- [ ] Click the `?` beside each label: the drawer opens with a summary, values, sources and related topics.
- [ ] Open the Mode, Language, Minimum severity, Topics and Servers dropdowns: each option has a short
  description under its label.
- [ ] Check the drawer and modal at phone width and in dark mode; no horizontal overflow.
- [ ] Save a destination, press Test, and confirm the delivery log still works.
- [ ] Switch a destination to digest/status and confirm the previous behaviour is unchanged.

## After updating

- [ ] The notification destinations and history are still there.
- [ ] `gamewarden update --check` says the running version is current.
