# GameWarden 0.3.0-dev.14

## Data impact

- **Update only** — no database or data-layout change.

## What changed

- **Test buttons use the saved configuration.** `Save & test` is now just **Test model** / **Test Discord**; the
  Owner presses **Save** first. The hint says so, and the buttons stay disabled with a visible reason until the
  model key / bot token and a channel exist.
- **Checklist results.** Each test shows one row per check with ✓/✕ and its detail: base URL, model id, API key,
  request and response for the model; bot token, guild, channel id, Discord login, channel and message for Discord.
  Latency is shown too.
- **Custom model headers.** A model request can carry extra HTTP headers (for example `X-Title` or an
  `api-key`-style header). `%apiKey%` inside a value is replaced with the saved model key; `Authorization: Bearer`
  stays the default unless a custom `Authorization` header is present.
- **API:** `POST /system/agent-host/test-model` and `POST /system/agent-host/test-discord` always return a check
  list, including expected failures such as a missing token or channel.

## What to test on the VM

- [ ] Fill the model fields, **Save**, then **Test model**: the checklist shows each step and the reply.
- [ ] Remove the model key, Save, **Test model**: the API key row is ✕ and the request is not sent.
- [ ] Add a custom header such as `X-Title: GameWarden`; test again against an endpoint that requires it.
- [ ] Save the bot token and system channel, **Test Discord**: the message arrives and every check is ✓.
- [ ] Clear the system channel, Save, **Test Discord**: the channel row is ✕ with a clear reason.
- [ ] Press Test without saving a changed field: the result reflects the **saved** values, as the hint says.

- [ ] The worlds are the expected ones.
