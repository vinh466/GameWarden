# GameWarden 0.3.0-dev.24

## Data impact

- **Update only** — Core adds `agent_model_calls` through migration `AgentModelCalls`. Existing data is not rewritten.
- The table stores redacted and truncated request/response previews (max 8,000 characters) plus latency, token
  counts, tool count, status, trace/run/turn and incident ids.

## What changed

- **Model observability.** Every chat and runbook-summary model call records its latency, prompt/completion tokens,
  tool count, status and a redacted request/response preview. Failures are recorded too.
- **Usage API.** `GET /api/v1/system/agent-host/usage?hours=24` returns turns, model calls, errors, tokens, average
  and max latency, pending approvals, open incidents and the 20 newest calls.
- **Panel: Agent activity (24h).** System → Operations now has a card with the metrics, a latency sparkline and a
  recent-model-calls table. **Details** opens the redacted request and response for that call, with its trace id.
- **Runbook summaries** are recorded with purpose `runbook.summarize` and the incident id, so an incident diagnosis
  can be traced back to the exact model call.

## What to test on the VM

- [ ] Open System → Operations; the **Agent activity (24h)** card shows non-zero turns/model calls after a chat.
- [ ] Ask the bot a status/log/mod question; the row appears with latency, tokens, tool count and `ok`.
- [ ] Make the model fail (wrong key or base URL); the row shows `error` and the error text.
- [ ] Press **Details** on a call: the redacted request/response preview opens; nothing secret is visible.
- [ ] Run a crash **Diagnose**: a `runbook.summarize` row appears and its trace id matches the incident.
- [ ] Let a write run: a `verification` row appears after the approval.
