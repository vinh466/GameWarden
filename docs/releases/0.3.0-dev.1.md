# GameWarden 0.3.0-dev.1

## Data impact

- **From `v0.2.0-rc.20`:** update only. The database schema is the same.
- **From `v0.2.0-rc.19` or older:** back up before updating. This build includes the observability
  migration that landed in rc.20, so the first start after the update may change the database.

Back up the usual folders before updating:

```text
C:\GameWarden\instances\<id>\data        worlds and saves
C:\GameWarden\db\gamewarden.db           servers, settings, Owner account
C:\GameWarden\instances\<id>\mods        if mods or configs changed
```

## What changed

- The development line is now forward-only: no rollback, no `version use`, no database snapshot and no
  *Switch back* card. A failed release is replaced by the next one; data may be reset when the notes say so.
- One release line: `vX.Y.Z-dev.N`. `System → Version & updates` now shows the newest release, when it was
  checked, the release notes and a backup warning, then one *Update* action.
- `gamewarden update` always takes the newest release; `--prerelease` and `--restore-db` are gone.
- `release.yml` now runs the same CI gate as `main`, requires the tag to be on `main`, and uses
  `docs/releases/<version>.md` as the GitHub release body.
- Includes the observability/Discord work from rc.20.

## What to test on the VM

- [ ] Open **System → Version & updates**: latest version, checked time, release notes, last result.
- [ ] Update from rc.20 (or older after the backup); the panel reconnects and the games keep running.
- [ ] Start a server and check its console and the Logs tab.
- [ ] `gamewarden update --check` says the running version is current.
- [ ] No *Switch back* and no channel control appear.

## After updating

- [ ] The server list still shows the instances and they start.
- [ ] The worlds and mod sets are the expected ones.
- [ ] If you came from rc.19 or older, confirm the database and instance settings survived.
