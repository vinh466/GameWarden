# GameWarden 0.3.0-dev.17

## Data impact

- **Update only** — no database or data-layout change.

## What changed

- **Agent debugging:** `GET /api/v1/agent/operations` returns the Operations Agent's sanitized configuration (enabled,
  bot connected, token/key set, guild, channel mapping, allowed users/roles, language, model, base URL, header names,
  approval limits) and the last error. It never returns the bot token, model key or header values. Requires
  `agent.system.settings`.
- **Discord test logging:** every Test Discord attempt logs the channel id and the result (Gateway/REST success or the
  failure), so a Core log shows which channel was tested.
- This is diagnostic only; the test behaviour is unchanged.

## What to test on the VM

- [ ] Update, then call `GET /api/v1/agent/operations` with an Agent token (or `gw_agent_get` → `/operations`):
  confirm the saved `system` and server channel ids are the ones you expect.
- [ ] Press **Test Discord** with a wrong channel id; Core logs the channel id and the failure.
- [ ] Press **Test Discord** with a text channel; Core logs `ok via REST` and the message arrives.
