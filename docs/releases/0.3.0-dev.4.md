# GameWarden 0.3.0-dev.4

## Data impact

- **From `v0.3.0-dev.3`, `v0.3.0-dev.2` or `v0.2.0-rc.20`:** update only. The database schema only adds the
  `notification_status` table; existing servers, worlds, settings and notification history stay.
- **From `v0.2.0-rc.19` or older:** back up before updating. The observability migration landed in
  `v0.2.0-rc.20`, so the first start after the update may change the database.

Back up the usual folders before updating from an older build:

```text
C:\GameWarden\instances\<id>\data        worlds and saves
C:\GameWarden\db\gamewarden.db           servers, settings, Owner account
C:\GameWarden\instances\<id>\mods        if mods or configs changed
```

## What changed

- **Digest mode:** events for one destination are grouped for `digestSec`, then sent as one Discord message;
  overflow is truncated to Discord's limits.
- **Status mode:** one message per status destination is posted once and edited in place every `intervalSec`
  when the rendered server state changes. A deleted status message is recreated; a webhook cannot pin it, so pin
  it once by hand in Discord.
- The Discord channel now supports `PATCH` for status edits and treats a missing status message as "recreate",
  not "disable the webhook".
- The panel exposes `instant`, `digest` and `status`, with hints for the digest window and manual pinning.
- No changes to the system log or the rest of the panel.

## What to test on the VM

- [ ] Add a destination with mode `instant`, press **Test**, then trigger a failed job or a crash: one message.
- [ ] Change the destination to mode `digest`, set `digestSec` to `30`, trigger two events, wait 30–40 seconds:
  one message containing both events.
- [ ] Change the destination to mode `status`, set `intervalSec` to `30`, start/stop a server: the same
  Discord message is edited in place, not a second message.
- [ ] Delete the status message in Discord, wait for the next interval: a new message appears and is stored.
- [ ] Pin the status message once by hand; later edits keep the pin.
- [ ] Check the delivery log: instant/digest deliveries show `sent`/`failed` and can be retried.
- [ ] Confirm the webhook URL is still hidden after saves.

## After updating

- [ ] Server list still shows the instances and they start.
- [ ] Existing notification destinations and history are still there.
- [ ] `gamewarden update --check` says the running version is current afterwards.
