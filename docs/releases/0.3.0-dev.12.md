# GameWarden 0.3.0-dev.12

## Data impact

- **Update only** — no database or data-layout change. `agent-host.json` values are read as written; the Discord ids
  in it are strings from this release on (a number in the old file is accepted and rewritten the next time the panel
  saves).

## What changed

- **Panel:** System has a new **Operations** tab for the Owner's Discord bot (docs/20): enable switch, connection and
  secret status, guild and one channel per server, allowed users/roles, language, bot token and model key (write-only),
  model limits, approval limits and the last error.
- **Fix:** Discord guild, channel, user and role ids are serialized as strings. Discord snowflakes are 64-bit and a
  JavaScript client loses precision above 2^53; the panel now keeps the exact id.
- The CLI and API use the same string form.

## What to test on the VM

- [ ] Open **System → Operations**: the status badges show enabled/connected and whether the token and model key are set.
- [ ] Paste the guild id and one channel id per server; Save; reload the page and confirm the same ids.
- [ ] Set the bot token and model key; restart `GameWardenCore`; the bot connects and `/status` answers.
- [ ] Toggle **Enable the Operations Agent** off, Save, restart Core: the bot stays offline.
- [ ] Check a large id (for example a real guild id) is unchanged after saving and reloading.

## After updating

- [ ] The worlds are the expected ones.
