# GameWarden 0.3.0-dev.22

## Data impact

- **Update only** — Core adds Operations Kernel tables and columns on start (EF Core migration
  `OperationsKernel`). Existing instances, worlds, jobs, mods and conversations are not rewritten.
- The new tables are `agent_incidents`, `agent_incident_events`, `agent_runbook_runs`,
  `agent_policy_decisions` and `agent_events`. Agent runs, tool calls and approvals gain trace/policy/execution
  columns.
- A backup of the data root is still the safe habit before a large jump, but this release does not require a
  restore/import.

## What changed

- **Operations Kernel (docs/21):** the Discord bot now runs through a kernel with capabilities, policy, approvals,
  incidents, runbooks and traces instead of a bare chat loop.
- **Context pack:** every turn receives the channel → instance mapping, server state, open jobs, pending approvals,
  open incidents, recent activity and local time. The prompt no longer starts blind.
- **Policy:** writes are evaluated by `AgentPolicyService`. The default is deny-writes; a matching rule can require
  approval, allow, or deny. Every decision is stored. An optional `agent-policy.json` in the data root overrides the
  defaults.
- **Approvals close the loop:** the approval card shows impact and local expiry; the interaction is deferred; after
  execution the tool result is fed back to the model for a read-only verification turn. A Core restart marks a
  running approval `unknown`, never silently retrying it.
- **Incidents:** `instance.crashed`, `instance.faulted`, repeated `job.failed` and user reports create an incident.
  The bot posts an incident card in the mapped channel, creates a thread, and offers **Diagnose**, **Restart** and
  **Silence**. Recovery/`job.succeeded` resolves it.
- **Runbooks:** `runbooks/generic.crash-triage.yaml` is loaded from the install folder; an Owner can add runbooks
  under the data root. This first runbook is read-only (status, instance, error log, mod log, model summary). Write
  steps stay behind the incident/approval path.
- **Bot notification channel:** a notification destination can use `channel = discord-bot`; events route by
  `instanceId` to the mapped server channel, with webhook destinations still available as fallback.
- **Discord UX:** `/pending`, `/help`, `/agent-off`, `/agent-on`; optional `/ask instance`; `/server instance`;
  `/approve` is scoped to the approval's channel; approval buttons are localized; `BotConnected` follows Discord
  connect/disconnect.
- **Panel:** System → Operations shows recent incidents, their timeline and a **Diagnose** action. Owner APIs expose
  incidents, approvals and traces.
- **New read tools:** `list_incidents`, `get_incident`, `get_notification_deliveries`, `check_update`.
- **Store:** Discord message ids, tool call ids and trace ids are now correlated across runs, approvals, incidents and
  notifications.

## What to test on the VM

- [ ] Update and let Core restart; the panel opens and existing servers still show the same state.
- [ ] `/status`, `/help`, `/pending`, `/agent-off`, `/agent-on` work; `/agent-off` makes other commands refuse until
  `/agent-on`.
- [ ] Ask for a status/log/mod check; inspect the panel Incidents card (it should be empty on a healthy day).
- [ ] Crash a test server (or use `FakeGame` on a dev box): an incident card appears in its channel, a thread is
  created, and **Diagnose** posts a read-only summary.
- [ ] Press **Restart** on the incident: an approval card appears; Approve runs the restart; the bot verifies and the
  incident resolves when the server is running.
- [ ] Ask for a write in chat: the approval card shows impact and local expiry; Approve leads to a verification
  answer, not only a raw tool result.
- [ ] Restart Core while an approval is running: the approval is marked `unknown` and the panel/API shows why.
- [ ] In System → Notifications, add a `discord-bot` destination for one server; a test message arrives in that
  server's mapped channel.
- [ ] Check the panel Incidents card after the test; the timeline contains the incident, diagnosis and approval
  events.

## After updating

- [ ] Server list still shows the instances and they start.
- [ ] The worlds are the expected ones.
- [ ] The panel opens on the dashboard; System shows the same version and update state as before.
- [ ] `agent-policy.json` is absent by default; the safe default policy applies. Add it only when you want to change
  who may do what.
