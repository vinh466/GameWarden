# GameWarden 0.3.0-dev.3

## Data impact

- **From `v0.3.0-dev.2`, `v0.3.0-dev.1` or `v0.2.0-rc.20`:** update only. The database schema is unchanged.
- **From `v0.2.0-rc.19` or older:** back up before updating. The observability migration landed in
  `v0.2.0-rc.20`, so the first start after the update may change the database.

Back up the usual folders before updating from an older build:

```text
C:\GameWarden\instances\<id>\data        worlds and saves
C:\GameWarden\db\gamewarden.db           servers, settings, Owner account
C:\GameWarden\instances\<id>\mods        if mods or configs changed
```

## What changed

- The system log now fills the instance, job and request fields from `ILogger` scopes case-insensitively,
  including ASP.NET's `RequestId`/`TraceIdentifier`.
- Instance logs use the `GameWarden.Instance.<id>` category when no scope is present, so the server filter
  works for existing rows as well.
- `JobService` and `ModsService` push `jobId`/`instanceId` scopes around a job, and the query can still find
  older job rows whose id is only in the message.
- No other runtime change from `v0.3.0-dev.2`.

## What to test on the VM

- [ ] Open **System → Logs**, filter by a server: rows from `GameWarden.Instance.<id>` appear.
- [ ] Run a job, then filter by its job id: the job's Core-side log rows appear.
- [ ] Filter by a request id (from a recent panel action) and confirm the HTTP request row matches.
- [ ] Open a row and check the exception/data drawer still works.
- [ ] `gamewarden update --check` says the running version is current afterwards.
- [ ] Discord notification settings and delivery log still show the same destinations and history.

## After updating

- [ ] Server list still shows the instances and they start.
- [ ] Existing log rows remain readable; new rows have the instance/job/request fields filled.
